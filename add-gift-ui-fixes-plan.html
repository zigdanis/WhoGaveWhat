Add Gift UI Fixes

Implementation plan for neutral gift relationships, reusable person selection, predictable calendar behavior, locale-aware currency, and content-sized sheets.

TLDR: Remove every implicit “You” assumption, make From and To share a live-filtered picker, separate calendar navigation from day selection, persist a locale-inferred currency preference, and let Add Gift move between fitted and full-height presentations.

Context

The current flow creates and special-cases a person whose ID is you, treats the sender differently from the recipient, conflates calendar navigation with selection, hardcodes ruble display, and presents several sheets at more height than their content requires.

The change must preserve existing gifts and SwiftData compatibility while making new stores and new gifts neutral about the user’s participation.

Constraints

  • Do not delete an existing legacy you record; it may already represent an ordinary renamed person.
  • Changing the currency preference changes display metadata only; it does not convert historical amounts.
  • Use stable person IDs and cached filtering so selection and focus survive SwiftUI updates.
  • Use xcodebuildmcp for all build, test, simulator, automation, and screenshot work.
  • Reuse an already booted simulator; otherwise prefer iPhone 17 Pro.

Proposed Approach

Neutral people and gift endpoints

Stop bootstrapping a self person, default both endpoint IDs to nil, and remove all ID-based behavior for you. Keep the existing paidByYou persistence field for compatibility, but never derive it from a person ID. Conservatively retain every existing legacy self record as an ordinary renameable and deletable person.

Shared person picker

Use the same picker for From and To. An observable picker state will cache filtered people, preserve an existing selection, provisionally select the first matching person as the query changes, and write that selection to the draft immediately so swipe dismissal keeps it. Row taps select and dismiss; Add creates or reuses an exact match, selects it, and dismisses.

Calendar and sheet sizing

Wrap UICalendarView so month and year navigation never triggers dismissal. Only its single-date delegate callback commits and closes; Today and Yesterday keep their current direct behavior. Present the date picker fitted to its content. Measure the collapsed Add Gift form for a compact detent and animate to full height when details are shown.

Currency preference

Persist an ISO-4217 code through the preferences gateway. Initialize it once from the current locale, falling back to USD, and expose a Settings picker. Replace hardcoded ruble formatting with locale-aware currency formatting using the selected code. Keep the approximate-value field empty until edited and show a formatted zero-value placeholder.

Work Plan

  1. Remove implicit self behavior. Update SwiftData initialization, draft defaults, save/direction logic, people deletion UI, and preview data. Add non-destructive legacy cleanup coverage.
  2. Unify person selection. Extract person-picker state and UI, connect both From and To, implement cached filtering and provisional selection, and add focused state/use-case tests.
  3. Fix date selection. Add the UIKit calendar bridge, retain quick-date buttons, and fit the date sheet to its content.
  4. Add currency preference. Extend preferences and composition, inject the selected code, add Settings UI, centralize formatting, and update every monetary display.
  5. Adapt Add Gift presentation. Add measured compact and large detents, expand on details, collapse when details hide, and retain scrolling and keyboard avoidance.
  6. Review and harden. Run an independent review, land each correction as a focused commit, re-review, and monitor the pull request until checks and feedback are clear.

Verification

  • Run the full test target through xcodebuildmcp simulator test.
  • Verify a fresh store has no “You” person and Add Gift opens compactly with unset endpoints.
  • Verify live person filtering, first-result checkmark, persisted swipe dismissal, row selection, and Add behavior for both endpoints.
  • Verify month/year navigation leaves the date sheet open; choosing a day or a preset closes it.
  • Verify the value field is empty with the selected currency’s zero placeholder.
  • Verify details expand Add Gift to full height and collapsing returns it to fitted height without keyboard clipping.
  • Change currency in Settings and verify immediate display updates plus persistence after relaunch.
  • Capture and visually inspect snapshots for the filtered person picker, navigated compact calendar, and expanded form.

Risks

  • Every existing legacy self record must remain because its identity may already have been repurposed through rename.
  • Calendar component conversion must consistently use the same locale, calendar, and time zone to avoid a one-day shift.
  • Measured detents must tolerate keyboard changes, long translations, and larger Dynamic Type without clipping.
  • App Store storefront inference is unavailable in the current architecture, so the initial currency is locale-derived as allowed.
